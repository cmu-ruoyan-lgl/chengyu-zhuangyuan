## 0. 决策前提（v0.2 已变更）

**v0.1 的冲突已消解。** 原冲突为：目标用户「中小学生 + 家长」与「1:1 复刻原版商业化」不兼容——未成年人在防沉迷规则下仅可在周五/六/日及法定节假日 20:00–21:00 游戏，周中 5 天不可进入，广告曝光量被压缩约 85–90%，付费上限使房屋升级收入线失效。

**已采用方案 A：目标用户调整为全年龄泛用户**（成年人为收入主盘，学生与中老年为覆盖盘）。由此带来的连锁变更：

| 项 | v0.1（中小学生） | v0.2（全年龄） |
|---|---|---|
| 收入模型 | 不成立 | 成立（广告 + 内购） |
| 难度曲线 | 保守（生僻封顶 25%） | 主线 25% + 支线放开至 40%（见 §3.2.2） |
| 字号 | 全量放大 | 默认中等 + 提供「大字模式」开关（见 §3.3.1） |
| 每日免费提示 | 曾建议 5 次 | 恢复原版 3 次（见 §3.5） |
| 合规 | 商业模型的致命约束 | 常规必做项（实名/防沉迷/付费上限仍须接入，见第 5 章） |
| 家长端学习报告 | 方案 B 的核心 | 降级为 P2 可选（错题本保留为 P0） |

**注意**：全年龄定位**并未免除**未成年人合规义务——只要用户群里可能出现未成年人，实名认证、防沉迷时段限制与付费上限就必须接入。第 5 章从「风险决策」改为「合规必做清单」。

## 1. 产品定义

### 1.1 Fun Hypothesis（一句话）

> 好玩的核心是：**在横竖交叉的双约束下，把一个你其实认识的成语从记忆里"抠"出来的那一下确定性**——不是"学会了一个成语"，是"我果然想起来了"。

这句话决定了所有设计取舍：填字必须是**回忆**而非**推理**，所以题库必须以高频成语为绝对主体；学习（释义/典故）是附加价值，不能喧宾夺主。

### 1.2 Design Pillars（4 条不可妥协）

| # | Pillar | 违反的代价 |
|---|---|---|
| P1 | **一眼看懂，一指通关**：任何界面不需要文字教程即可操作 | 中老年与小龄用户首关流失 |
| P2 | **卡壳有出路，但不廉价**：提示有限，但交叉约束本身提供自救路径 | 无限提示 → 玩法退化为点提示 |
| P3 | **每次点击都有即时反馈**：填对/填错/完成必须在 100ms 内有视觉+音效响应 | "感觉不对"类差评的主要来源 |
| P4 | **成长看得见**：官职与府邸的进度必须数字与画面同步变化 | 长线留存断裂 |

### 1.3 目标用户与使用情境

| 维度 | 定义 |
|---|---|
| 主用户 | 25–50 岁泛用户（通勤/碎片时间，成语储备中等，付费与广告价值主体） |
| 重要覆盖盘 | 中老年用户（50+，怀旧、门槛敏感、字号敏感、广告接受度高） |
| 次要盘 | 学生与家长（受防沉迷约束，贡献口碑与长尾，不贡献主要收入） |
| 场景 | 通勤、排队、饭后、睡前；单手竖屏 |
| 核心诉求（成人） | 不费脑的成就感、能推进的进度条、不卡关也不无聊 |
| 核心诉求（中老年） | 看得清、点得准、不催我、别扣钱 |
| 核心诉求（学生/家长） | 玩的是"有用的东西"（释义/典故/错题本为价值点） |

**用户对难度的影响**：全年龄盘口意味着**难度曲线的两头都要照顾**——前 50 关必须让中老年与低龄用户零挫败（生僻 ≤8%），后期必须让成语爱好者有挑战（支线放开至 40%）。这条张力在 §3.2.2 用「主线封顶 + 支线放开」解决。

### 1.4 差异化定位

按「1:1 复刻」策略，**本版不做玩法差异化**。原版已有结构完整保留（见第 2 章）。所有我认为应当调整的地方，集中在第 5 章以「风险 + 方案」形式给出，不擅自改动复刻范围。

## 2. 原版拆解（Mechanic Biopsy）

### 2.1 核心循环一句话

底部备选汉字 → 点击填入上方成语矩阵空格 → 横竖方向全部构成完整四字成语 → 通关 → 产出金币 → 消耗金币升级府邸/招募门客 → 累计关卡数晋升官职 → 解锁更高难度关卡。

### 2.2 三层循环

| 层级 | 时间尺度 | 结构 | 保留钩子的东西 |
|---|---|---|---|
| **Moment-to-moment** | 0–30s | 观察空格 → 选字 → 填入 → 即时判定（对/错/完成） | 填字入格的手感、交叉点被"验证"的快感 |
| **Session loop** | 2–5 min（本次定 2–3 min） | 进关 → 消耗体力 → 闯 3–5 关 → 体力耗尽 → 领奖励/升级府邸 | 体力耗尽时的"再开一局"与广告位 |
| **Long-term** | 天–周 | 官职晋升（童生→状元）+ 府邸扩建 + 门客收集 + 成就 | 段位感、收集欲、家长可见的学习成果 |

### 2.3 系统地图与交互矩阵

原版并存 6 个系统：① 填字闯关（核心）② 官职晋升 ③ 府邸扩建 ④ 门客收集 ⑤ 道具/体力 ⑥ 支线玩法（看图猜成语、限时答题、好友 PK）。

交互标注：**intended** = 设计意图内的正向耦合；**acceptable** = 可接受的副作用；**risk** = 存在打架风险。

| | ②官职 | ③府邸 | ④门客 | ⑤道具/体力 | ⑥支线 |
|---|---|---|---|---|---|
| **①填字** | intended（关卡数→官职） | intended（金币→扩建） | intended（金币→招募） | risk（体力截断核心乐趣） | acceptable（分流主线） |
| **②官职** | — | acceptable（双进度线） | acceptable | acceptable | acceptable |
| **③府邸** | — | — | acceptable | **risk**（升级耗金币与买提示抢同一资源） | acceptable |
| **④门客** | — | — | — | acceptable（产出金币，缓解抢资源） | acceptable |
| **⑤道具/体力** | — | — | — | — | acceptable |

**两条 risk 是原版被投诉的根源**：体力截断（打断心流）与府邸/提示抢同一资源（逼氪感）。复刻时保留，但第 5 章提出解法。

### 2.4 关卡结构解剖

**基础单元**：一个 N×N 汉字网格，横竖方向各自构成四字成语，成语之间共享交叉字。

**两条约束同时成立**：
1. **横向/纵向完整性**：每个方向必须拼出合法四字成语；
2. **成语链接续性**（原版特色）：相邻成语首尾相接，如「以偏概全 → 一概而论 → 论功行赏 → 上行下效」。

**实例拆解（原版第 34 关）**：横向含「恨之入骨、怀恨在心、轩然大波、余波未平、感恩戴德、以德报怨、怨天怨地、铺天盖地」，竖向含「毛骨悚然、平铺直叙、是非曲直」。玩家的自然解法是**先解确定项（毛骨悚然），再用交叉字反推**，而非逐字试错——这是本玩法真正的策略深度来源。

**难度演进的三个杠杆**：

| 杠杆 | 低难度 | 高难度 | 玩家体验变化 |
|---|---|---|---|
| 网格尺寸 | 4×4 | 8×8（原版后期据称达 10×10，数据来源为第三方下载站，**存疑**） | 视觉复杂度、扫视成本 |
| 成语条数 | 2–3 条 | 6+ 条 | 记忆提取次数 |
| 交叉点数量 | 1–2 | 5–8 | 必须先解"锚点成语"的依赖深度 |
| 生僻度 | 全部高频 | 含冷门典故 | 从"回忆"退化为"猜" |

**关键设计规律**：生僻度是唯一会摧毁 Fun Hypothesis 的杠杆。生僻成语把「我果然想起来了」变成「我根本不认识」，玩家从主动回忆转为被动查词典，退出率陡升。原版 2025 年更新降低冷门成语出现频率约 60%，印证了这一点。

### 2.5 UI 结构拆解

原版为竖屏单手布局，自上而下五个功能区：

| 区域 | 位置 | 内容 | 设计作用 |
|---|---|---|---|
| ① 状态条 | 顶部 | 体力、金币、关卡号、官职 | 资源与进度常驻可见 |
| ② 成语矩阵 | 中部（约占屏 45–50%） | 空格 + 已填汉字 + 交叉高亮 | 主战场，视觉焦点 |
| ③ 备选字区 | 下部（约占屏 25%） | 12–20 个候选汉字块 | 操作区，拇指可达 |
| ④ 道具栏 | 底部 | 提示 / 撤销 / 洗牌 | 卡壳出口 |
| ⑤ 结算层 | 覆盖层 | 通关动画、释义卡、金币结算 | 反馈与价值交付 |

**反馈通道诊断**（原版做得好与不够好的地方）：

| 通道 | 原版表现 | 评价 |
|---|---|---|
| 视觉 | 填对时格子高亮 + 成语整体点亮 | 强，符合 P3 |
| 视觉 | 交叉点被双向验证时的连锁点亮 | 强，这是玩法的爽点峰值 |
| 音频 | 轻柔古典音效 | 中性，缺少"填对"专属正反馈音（复刻可补） |
| 触觉 | 无 | 缺失项，移动端低成本高收益（振动 10–15ms） |
| UI | 错误撤回一键可达 | 强，降低试错心理成本 |

**可优化点**：结算层的成语释义卡是家长价值的核心，但原版把它放在通关后弹窗，学生往往直接跳过。复刻建议保留原版结构（不擅自改），但在第 5 章方案 C 中提出「错题本 / 学习报告」作为家长端差异化钩子。

### 2.6 经济系统：Sources & Sinks

| Sources（产出） | 速率/条件 | Sinks（消耗） | 说明 |
|---|---|---|---|
| 通关金币 | 每关固定 | 府邸升级 | 主线消耗 |
| 连续答对加成（文思泉涌） | 连对触发 | 门客招募/升级 | 长线消耗 |
| 门客挂机产出 | 按小时 | 道具购买（提示/跳过/洗牌） | 与府邸抢资源 **risk** |
| 每日签到 / 任务 | 每日 | 体力补充 | 卡点变现 |
| 成就奖励 | 一次性 | | |
| 广告奖励（双倍卡等） | 看广告 | | |

**通胀风险评估**：门客挂机产出是**无上限的 source**，若缺少对应 sink，中期金币必然通胀、府邸升级失去意义。原版用「府邸等级上限 + 门客升级消耗递增」对冲。复刻必须保留该对冲，否则 30 天后经济崩溃。

### 2.7 商业化结构

| 收入线 | 原版做法 | 复刻取舍 |
|---|---|---|
| 激励视频广告 | 换体力、提示、双倍金币 | 保留 |
| 内购 | 金币包、去广告、房屋加速 | 保留结构，**受未成年人付费上限约束**（第 5 章） |
| 插屏广告 | 关卡间 | 保留 |

### 2.8 拆解结论：原版做对了什么、问题在哪

| 判断 | 依据 |
|---|---|
| ✅ 填字核心是健康机制 | 交叉约束提供真实策略深度，不依赖随机性 |
| ✅ 养成与解谜深度绑定 | 答题产出直接作用于家园，成长反馈直观 |
| ✅ 知识附加值是差异化护城河 | 释义/出处/错题本，是家长付费意愿的来源 |
| ⚠️ 体力卡点打断心流 | 2–3 分钟单局 + 体力截断，容易在爽点上被强制中断 |
| ⚠️ 金币三重争抢（府邸/门客/道具） | 玩家体感为逼氪，是被投诉点 |
| ⚠️ 生僻成语比例曾过高 | 原版已下调 60%，说明该杠杆踩过坑 |

## 3. 复刻版产品设计

### 3.1 核心玩法规格

| 项 | 规格 |
|---|---|
| **Purpose** | 用最低操作成本提供"回忆成功"的高频小胜利 |
| **Player Experience Goal** | 每 15–20 秒获得一次"想起来了"的确定感 |
| **Inputs** | 触摸：点击空格选中 → 点击备选字填入；或点击备选字 → 点击空格（两种均支持，原版为前者） |
| **Outputs** | 格子填充、成语点亮、进度更新、金币结算 |
| **Edge Cases** | ① 同一字在多个成语中复用 ② 多音字/多义字导致多个候选合法 ③ 备选字多于所需字数（干扰项）④ 填错后撤回 ⑤ 中途退出进度保存 |
| **Failure States** | ① 无解（生成器 bug）② 体力耗尽 ③ 全部提示用完且玩家无法自行解出 |

**关键规则**：干扰字机制（备选字数量 > 所需字数）是难度杠杆之一，但必须保证**所需字 100% 在备选区内**——这条是硬约束，违反即 Failure State ①。

### 3.2 关卡系统

#### 3.2.1 生成规则（硬约束）

1. 网格内每个方向的连续 4 格必须构成合法四字成语；
2. 相交格必须同时属于横竖两条成语，且字符一致；
3. 成语链若启用接龙规则，后一成语首字 = 前一成语尾字；
4. 所有目标字必须出现在备选区；备选区 = 目标字 + 干扰字；
5. 每条成语在题库中必须存在于**已解锁难度层**；
6. 生成器必须输出唯一解或至少一条可推导路径（用锚点成语反推链验证）。

#### 3.2.2 难度曲线（MVP 300 关）

| 关卡段 | 网格 | 成语条数 | 交叉点 | 生僻成语占比 | 干扰字 | 目标单关时长 | Rationale |
|---|---|---|---|---|---|---|---|
| 1–50（入门） | 4×4 | 2–3 | 1–2 | ≤8% | 0–2 | 60–90s | 前 10 关必须零挫败；入门段要同时接得住中老年与低龄用户 |
| 51–150（进阶） | 5×5–6×6 | 3–4 | 2–4 | ≤18% | 2–4 | 90–120s | 交叉点 ≥2 才产生"先解锚点"的策略感 |
| 151–300（专业） | 6×6–7×7 | 4–6 | 4–8 | ≤25% | 4–6 | 120–180s | 上限守住 2–3 分钟单局；生僻度封顶 25% 防止退化为猜 |
| 支线·典故挑战 | 7×7–8×8 | 5–7 | 5–8 | ≤40% | 6–8 | 150–210s | 主动选择的高难模式，为成语爱好者提供上限 |

> **生僻占比 25% 封顶的 rationale**：超过该值，单关内出现 ≥2 条不认识成语的概率显著上升，玩家从主动回忆切换为放弃/查词典，直接违背 §1.1 Fun Hypothesis。原版下调冷门频率 60% 是同一问题的实证。
>
> **「主线封顶 + 支线放开」是全年龄定位的解题方式**：主线面向所有人不设知识门槛（≤25%），但成语爱好者会嫌无聊——所以把高生僻度放进**主动选择**的支线「典故挑战」（≤40%）。玩家自己选择难度，比系统替他决定更安全。此数值为 `[PLACEHOLDER · 需 A/B 验证]`。

#### 3.2.3 卡点设计

| 卡点类型 | 出现节奏 | 设计意图 | 出口 |
|---|---|---|---|
| 体力耗尽 | 连续 8–12 关 | 控制单日时长、制造回归理由 | 等待恢复 / 看广告 / 道具 |
| 难度台阶 | 每 50 关一次跃迁 | 制造"我变强了"的阶段性证明 | 提示道具 + 上一关积累的金币 |
| 生僻词墙 | 每 30 关集中 1 次 | 短时挫败 → 提示消耗 → 广告曝光 | 提示 / 跳过卡 |

**纪律要求**：难度台阶的跃迁幅度**不得**同时提升两个以上杠杆（如网格变大同时生僻度提高 = 违规），否则失败信号 B 必然触发。

#### 3.2.4 题库分层

| 层 | 词量目标 | 来源 | 状态 |
|---|---|---|---|
| L1 高频 | 800–1200 条 | 中小学教材高频成语 + 日常用语 | 需采购/整理 |
| L2 中频 | 2000–3000 条 | 常用成语词典 | 需采购/整理 |
| L3 冷门 | 1000–2000 条 | 典故类成语（附出处） | 需采购/整理 |
| 合计（MVP） | ≥3800 条 | — | **MVP 关卡生成所需最低量** |

> 原版宣称 3 万+ 题库（第三方站点数据，**存疑**）。MVP 阶段 3800 条足以生成 300 关且不重复；长期需扩至 1 万+ 支撑 1000 关。

每条成语数据结构必须包含：`idiom / pinyin / meaning / source / example / difficulty_level / tags`。释义是家长价值交付物，不可省略。

### 3.3 UI 设计规格

#### 3.3.1 屏幕分区（竖屏 1080×1920 基准）

| 区 | 高度占比 | 关键元素 | 字号（基准） |
|---|---|---|---|
| 状态条 | 8% | 体力、金币、关卡号、官职徽章 | 26sp |
| 成语矩阵 | 48% | 格子（含交叉高亮）、已填汉字 | 汉字 40sp |
| 备选字区 | 26% | 汉字块，4–6 列网格 | 汉字 36sp |
| 道具栏 | 12% | 提示 / 撤销 / 洗牌 | 图标 96px |
| 安全区 | 6% | 结算/弹窗触发区 | — |

**字号 rationale**：全年龄盘口下，默认按**中等字号**（矩阵 40sp）保证信息密度与美观；同时必须提供 **「大字模式」开关**（矩阵 48sp / 备选 44sp / 状态条 32sp），服务中老年用户——这是一个设置项，不是两套 UI。默认关闭。

**全年龄适配的三条硬要求**：
1. 所有可点击元素最小触控区 ≥ 88px（含格子与备选字块），中老年与小屏同时受益；
2. 关键操作（填入、撤销、确认）不得依赖长按、滑动、双击等隐式手势；
3. 错误操作必须可无损撤回（撤销无限次），降低全年龄段的试错心理成本。

#### 3.3.2 状态机

```
Boot → Home(府邸/官职概览) → LevelSelect → Playing
Playing → [填字] → CheckCell → (对: 点亮 / 错: 抖动+提示撤回)
Playing → 全部成语成立 → Result(结算+释义卡) → 下一关 / Home
Playing → 体力不足 → StaminaGate(等待/广告/道具)
Playing → 提示耗尽且停滞 60s → HintOffer(广告换提示)
```

#### 3.3.3 反馈定义（P3 落地）

| 事件 | 视觉 | 音效 | 触觉 | 时限 |
|---|---|---|---|---|
| 选中空格 | 边框高亮 | 无 | 无 | <100ms |
| 填字正确 | 格子填充 + 笔画动画 | 清脆单音 | 振动 10ms | <100ms |
| 填字错误 | 抖动 + 红色描边 | 低沉短音 | 无 | <150ms |
| 单条成语完成 | 整条流光点亮 | 上升音阶 | 振动 15ms | 300–500ms |
| 交叉点双向验证 | 交叉格特殊辉光 | 双音和声 | 振动 20ms | 500ms |
| 通关 | 全矩阵点亮 + 金币飞入 | 完整胜利音 | 无 | 800–1200ms |

> 触觉反馈为原版缺失项，属低成本高收益补强，列入 MVP。

## 4. 技术方案（TapTap Maker / UrhoX Lua）

### 4.1 架构分层

```
数据层  data/        题库 JSON、关卡 JSON、配置表（纯数据，无逻辑）
逻辑层  scripts/     core（填字判定、关卡状态机）、econ（金币/体力）、progress（官职/府邸/门客）
UI 层   scripts/ui/  NanoVG + Yoga 构建界面，只读逻辑层状态
存档层  scripts/save/ 本地 + 云存档（clientCloud / serverCloud）
```

纪律：UI 层不持有游戏状态；逻辑层不触碰 UI 控件。

### 4.2 目录结构（建议）

```

  image/          格子、按钮、府邸各级立绘、门客头像

data/
  idioms.json     题库（含释义/出处/难度）
  levels/         关卡数据（可由生成器离线产出）
  config.json     数值配置（体力、金币、道具价格）
scripts/
  core/grid.lua       网格与交叉约束
  core/validator.lua  成语合法性 + 通关判定
  core/level.lua      关卡状态机
  econ/stamina.lua    体力
  econ/currency.lua   金币与门客产出
  progress/rank.lua   官职
  progress/manor.lua  府邸
  ui/                 界面
  save/               存档
```

## 5. 合规必做清单（全年龄定位下仍然生效）

**定位改为全年龄，不等于免除未成年人合规义务。** 只要用户群中可能出现未成年人，以下四项就必须接入——这是法律要求，不是产品选择。区别在于：全年龄定位下，未成年用户只占少数，合规不影响整体商业模型，因此从「风险决策」降级为「常规必做项」。

### 5.1 必做项清单

| # | 项 | 要求 | 落地模块 |
|---|---|---|---|
| 1 | **实名认证** | 接入平台实名；未实名不得进入游戏 | `scripts/system/realname.lua` |
| 2 | **防沉迷时段** | 未成年账号：仅周五/六/日及法定节假日 20:00–21:00 可玩，每日 1 小时 | `scripts/system/antiaddiction.lua` |
| 3 | **付费上限** | 8 岁以下禁止付费；8–16 岁单次 ≤50 元、月 ≤200 元；16–18 岁单次 ≤100 元、月 ≤400 元 | `scripts/shop/iap.lua` |
| 4 | **适龄提示** | 登录页展示适龄提示；健康游戏忠告 | `scripts/ui/pages/login.lua` |

### 5.2 广告合规

- 激励视频不得含诱导性文案（不得出现"不看完无法继续"的强制逻辑）；
- **体力卡点必须保留免费出口**（等待自然恢复），广告只是加速选项而非唯一出路——这条同时也是 §2.3 中 risk 的解法；
- 未成年账号不展示个性化广告。

### 5.3 版号

商业化运营需游戏版号。若定位含教育属性，仍需评估是否落入游戏范畴——**此为法务判断，不在本文档结论内**，开发排期不应假设版号已就绪。

### 5.4 已废弃的备选方案（留档）

| 方案 | 做法 | 状态 |
|---|---|---|
| A. 调整目标用户 | 改为全年龄泛用户，保留 1:1 商业化 | ✅ **已采用**（v0.2） |
| B. 保留学生用户，改造变现 | 家长端售卖学习报告/词库包 | ❌ 未采用；其中「错题本」保留为 P0，学习报告降级 P2 |

## 7. 验收标准、埋点与 Playtest

### 7.1 核心指标假设 `[PLACEHOLDER · 全部需实测]`

| 指标 | 目标 | 说明 |
|---|---|---|
| 首关完成率 | ≥90% | 低于此值说明引导或字号有问题 |
| 单关平均时长 | 90–150s | 超出即网格/生僻度超标 |
| D1 留存 | ≥30% | 全年龄休闲益智参考值，需实测校准（原 35% 基于学生盘，全年龄盘应下调预期） |
| 提示使用率 | ≤40% | 高于此值说明难度曲线过陡 |
| 第 3 关退出率 | ≤15% | 见失败信号 A |
| 大字模式开启率 | 观察项 | 若 >25%，说明默认字号对主力盘偏小，应上调默认值 |

> **全年龄盘口的指标纪律**：必须**分年龄段看指标**。合并数据会掩盖问题——中老年在第 3 关流失、成人在第 200 关流失，合并后可能都显示"正常"。埋点需带年龄分段字段（来自实名，仅用于统计）。

### 7.2 埋点清单（最小集）

`level_start / level_end(duration, hints_used, wrong_count) / cell_fill(correct) / stamina_gate_show / ad_request / ad_complete / rank_up / manor_upgrade / follower_recruit / hint_used / wrong_book_add`

### 7.3 失败信号（先定义"坏掉长什么样"）

| 信号 | 判定条件 | 归因方向 |
|---|---|---|
| **A · 入门失败** | 第 3 关退出率 > 25% | 引导/字号/首关难度，而非题库量 |
| **B · 单关超时** | 单关平均时长 > 180s | 网格过大或生僻度超标（§3.2.2 杠杆越界） |
| **C · 难度过陡** | 提示使用率 > 60% 且 D1 < 30% | 难度台阶跃迁幅度违规（同时动了多个杠杆） |

**纪律**：playtest 前必须把这三个阈值写进测试脚本；未定义失败信号的 playtest 等于没做。
