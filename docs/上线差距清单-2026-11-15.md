## 结论

游戏本体、构建、文案素材都已就绪，但**还不能提审**。归纳为三类硬门槛：

1. **真机三局自测尚未完成** —— 但**通道已定位**：包体其实一直在后台（16 个 Spark 版本），
   此前扫的是 Maker 面板 `type=debug` 码（指向空的实时调试目录）；正确入口是后台
   `get-test-qr-code` 出的 `type=develop` 自测码，已交付 `artifacts/test-qr-spark-16.png`，
   待用户扫码连玩三局；
2. **商店物料未上传** —— `app analyze-status` 明确 3 个必填项缺失
   （`promotion_material_type` / `banner_4` / `screenshots`），且**尚未选择主包体**（`current_bindings: []`）；
3. **合规与协议未齐** —— 隐私、实名防沉迷、备案/适龄、以及制造游戏特有的《创意工坊内容授权协议》。

关于 SCE 协议：官方文档明确「关卡 / TapTap 制造游戏提审前须先签《创意工坊内容授权协议》」，
缺失时应返回 `SCE_AGREEMENT_REQUIRED`；**但本次实测 `analyze-status` 未返回该 blocker**，
以后台实况为准，签署属法律行为须用户明确同意。`analyze-status` 的 warnings 另有
`QUALIFICATION_FACTS_UNCONFIRMED`（资质判断事实未确认）与 `AGE_GRADE_REQUIRED`（适龄分级待补齐）。

## 清单 C：CLI 能力边界（别指望它一步到位）

**能帮**：`analyze-status`（查缺口）、`qualification get-assessment`（查资质）、
`get-module` / `save-changes`（改资料）、`upload`（传图标截图）、
`list-packages` / `+bind-spark-version`（查/绑已有制造版本）、测试计划、
`prepare-review-snapshot` / `precheck-review`（预检）、`submit-review`（提审，需确认）。

**不能帮**：

- 上传 Tap 小游戏新包体（官方文档：目前在控制台完成）
- Maker 发布面板「更新测试版」（RISK 18.0 的阻塞点，两条管线不同）
- 接实名 SDK、托管隐私政策、拍真机截图、替用户签协议或点提审确认

官方 §7 要求：提交审核、撤销审核、上线、下线等动作**必须单独说明并取得确认**，不得批量连续执行。

## 建议的推进顺序

1. 完成 `taptap-cli auth login` 授权（设备码 5 分钟有效，过期重新生成）；
2. 登录后我跑**只读**：`developer +list`、`app +list`、`app analyze-status`、
   `qualification get-assessment`、`app list-packages` —— 得到平台侧的权威缺口；
3. 优先修真机通道：Maker 发布面板「更新测试版」重试，或查是否有可绑定的 Spark 版本；
4. 真机跑三局 → 截 5 张 9:16 实机图 → CLI 上传图标/截图/封面；
5. 与用户逐项确认后：关内购/广告 → 补隐私 URL → 签 SCE 协议 → 资质提交 → 预检；
6. 预检通过后**单独确认**再 `submit-review`；审核通过 ≠ 已上线，上线是独立动作。

> 政策会变，最终以开发者后台当页提示和 `analyze-status` 返回为准，不要凭文档推断。
