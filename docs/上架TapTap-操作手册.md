# 上架 TapTap 操作手册（成语小秀才）

> 适用：TapTap 制造（maker.taptap.cn）本地开发项目 → Tap 小游戏上架。
> 口径来源：TapTap 开发者中心官方文档（developer.taptap.cn）+ TapTap 制造发布文档，2026-10-24 核对。
> 政策会变，提交前以开发者后台当页提示为准。

---

## 0. 先选路线（这一步决定后面所有工作）

官方资质矩阵（developer.taptap.cn 快速入门指南）：

| 游戏性质 | 需要的资质 | 上线形式 |
|---|---|---|
| 联网 + **有内购** | 游戏版号、软件著作权、**ICP 备案**、防沉迷、隐私合规 | 正式上线 |
| 联网 + 无内购 | ICP 备案、防沉迷、隐私合规 | **开放试玩** |
| 不联网 + 有内购 | 游戏版号、软著、防沉迷、隐私合规 | 正式上线 |
| 不联网 + 无内购 | 防沉迷、隐私合规 | **开放试玩** |

关键点：**没有版号就不能开内购**，只能以「开放试玩」形式上架；但**无论有没有版号，实名与防沉迷都是强制底线**（国家新闻出版署 2021 新规，测试阶段亦不例外）。

**本项目建议：两步走**

1. **第一步（现在就能做）**：以「开放试玩」上架 —— 关闭内购与广告变现，先拿真实玩家反馈和留存数据。
2. **第二步（资质到手后）**：补齐版号 + 软著 + ICP 备案，转「正式上线」，再开内购与激励视频广告。

理由：版号从申请到批复通常以月计、且个人主体办理门槛高；而游戏本体已经完整可玩，没必要等。

---

## 1. 账号与开发者认证（约 2 个工作日）

1. 注册并**实名认证**一个 TapTap 账号。
2. 打开 <https://developer.taptap.cn> → 进入控制台 → 申请入驻。
3. 开发者类型必须选 **认证开发者**（注册开发者最多建 2 个「未发布」游戏，且**无法提交审核**）：
   - 个人主体：厂商名称、开发者姓名、常用地址、**身份证正反面扫描件**、邮箱与已验证手机号
   - 企业主体：厂商名称、单位名称、注册地址、统一社会信用代码、**营业执照扫描件、认证公函**、紧急联系人
4. 提交后 TapTap 运营团队约 **2 个工作日**完成审核，结果在账号「通知」里看。
5. 想接广告/内购结算：开发者中心 → 财务与管理 → 配置**财务主体**。

> 提示：注册开发者后续可在 财务与管理 → 厂商设置 → 成为认证开发者 处升级，不用重新建号。

---

## 2. 生成最终游戏包（在 TapTap 制造里）

1. 在 maker.taptap.cn 打开本项目 → 确认本地代码已推送且远端构建成功（我们已构建过，App ID `8c6c5aec-0fbd-4606-b442-56ed62def573`）。
2. 点「构建游戏包」生成**最新版本**（每次改完代码都要重新构建）。
3. 打开**发布面板**，确认「发布厂商」是你上一步认证的厂商（只有一个厂商时会自动选中）。

---

## 3. 准备物料（缺一项发布按钮就不亮）

发布面板的前置条件（官方文档口径）：

| 物料 | 要求 |
|---|---|
| 游戏图标 | 必填 |
| 游戏截图 | **至少 3 张**，9:16 竖屏，实机截图 |
| 宣传图 / 横版封面 / 竖版封面 | 必填 |
| 方形宣传图 | 竖屏游戏需要 |
| 实机测试视频 | **首次正式发布需要** |
| 游戏名称 | 必填 |
| 游戏简介 | 至少 10 个字 |
| 开发者的话 | 至少 10 个字 |

本项目建议截这 5 张（对应我们已完成的页面）：

1. 主页（主菜单）
2. 棋盘页（填字中，最好有一两个成语已达成）
3. 通关弹层（印章 + 释义卡）
4. 府邸页（官职/门客/签到）
5. 图鉴页（已收录成语）

> 注意：截图必须是**你自己实机截的**，不要用过场动画/空白页/AI 生成图；发布面板内的操作**不消耗创作积分**。

---

## 4. 实机测试（强烈建议，别跳过）

1. 发布面板 →「扫码在手机上测试」→ 点**「更新测试版」**。
2. 手机装较新版本的 TapTap 客户端，扫码体验。
3. 发现问题时，在游戏内菜单用「问题回传」，然后回到项目对话里让 AI 拉反馈日志排查。
4. 改完代码/配置/物料 → **必须再次点「更新测试版」**，否则扫码还是旧版本。

补充：发布面板也提供分享链接，最多 100 人参与测试；但分享链接不验证 TapTap 容器环境，正式链路验证务必用实机二维码。

---

## 5. 上架前，把商业化关掉（开放试玩路线必做）

开放试玩**不允许开放内购**。在 `assets/data/config.json` 里做两处改动，改完重新构建：

1. **关内购**：把 `iap.products` 清空为 `[]`（商店页会自动只剩说明，不出现购买按钮）。
2. **关广告位**：把 `ad.placements` 清空为 `[]`（不再出现激励视频入口）。

> 我们代码里的广告是 mock（模拟播放，未接 SDK），内购也是占位实现——两者在真实变现前都不产生收入，先关掉最稳妥，也避免审核被卡。

另外两项必须在后台/配置补齐：

3. **隐私政策 URL**：把你的隐私政策页面托管后，填进 `config.compliance.privacy_url`；未托管时登录页不展示（我们不编造假链接）。
4. **防沉迷与实名**：当前是**占位认证**（自报年龄段）。正式上架必须接入实名认证 SDK（TapTap 侧可用平台实名/防沉迷能力），接好后用真实的 `Game.setRealname(年龄)` 回调替换登录页的占位逻辑。

---

## 6. 提交审核（1–3 个工作日）

两条路径二选一：

**A. TapTap 制造发布面板（推荐，一键）**
填完物料 → 确认发布 → 面板会检查完整物料与文案 → 通过后进入审核。

**B. 开发者后台传统流程**
建游戏（状态：草稿）→ 传包体 → **自测**（必须能正常启动）→ 补资料 → 提审。
操作要点：端侧配置选「未接入」平台防沉迷（若自行接入则如实选），安卓端需完成 TapPlay 测试，隐私说明可选择「使用 TapTap 通用声明」。

审核通常 **1–3 天**。常见驳回原因与规避：

| 驳回原因 | 规避 |
|---|---|
| 玩法同质化 | 保留我们已有的原创系统：官职晋升、门客挂机、错题本、每日挑战、成就 |
| 内容太短/玩法单一 | 我们已有 300 关 + 图鉴 + 成就，属完整作品 |
| 缺隐私政策/防沉迷 | 按第 5 节补齐 |
| 无法启动/闪退/报错 | 提审前真机完整跑一遍主流程 |
| 截图比例错乱 | 全部在电脑端后台重传 9:16 截图 |

---

## 7. 上架之后

- 版本更新：每次改动 → 重新构建 → 发布面板更新版本 → 重新提交审核。
- 数据：开发者后台看新增、留存、时长、关卡漏斗（哪关流失最多）。
- 运营节奏：不要一次更完所有内容，保持小步快跑，更新本身会带来曝光。
- 转正式上线：拿到版号 + 软著 + ICP 备案后，恢复 `iap.products` / `ad.placements` 并接入真实 SDK，转「正式上线」。
